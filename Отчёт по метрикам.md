# Отчёт по сбору метрик GuardLab

Настроен метрик приложения GuardLab и PostgreSQL в Minikube. 
Для хранения метрик используется VictoriaMetrics, для их сбора vmagent. 
Данные собираются по модели Pull: vmagent периодически обращается к endpoint с метриками

## Стек

- Backend: ASP.NET Core на .NET 10
- База данных: PostgreSQL 17
- Метрики приложения: prometheus-net.AspNetCore и prometheus-net.DotNetRuntime
- Метрики PostgreSQL: postgres-exporter
- Хранение и сбор: VictoriaMetrics Single и vmagent, Helm chart
- Kubernetes-кластер: Minikube

## Как устроен сбор
vmagent ищет поды в namespace guardlab 
через Kubernetes sd с ролью pod. Для сбора выбираются поды с аннотацией prometheus.io/scrape: "true"
Путь и порт метрик vmagent получает из аннотаций prometheus.io/path и prometheus.io/port

API отдаёт метрики по адресу /metrics на порту 8080.
Для PostgreSQL в тот же Pod добавлен контейнер postgres-exporter - Он отдаёт метрики на порту 9187.
Метрики хранятся 7 дней - можно редачить через конфигурацию

## Метрики приложения
Для HTTP-запросов используется мидлварь из prometheus-net.AspNetCore.
В метриках сохраняются HTTP-метод и полный код ответа. 
используется шаблон маршрута, например /api/labs/{slug} - полный url не пишется, т.к. иначе будет высокая кардинальность ;

Для метрик .NET Runtime в приложении запускается prometheus-net.DotNetRuntime. 
Он собирает технические показатели

В приложении также добавлены четыре собственные бизнес-метрики:

guardlab_lab_runs_total - метка result: success или rejected. Считает успешные и отклонённые запуски лабораторий.

guardlab_lab_key_access_total - метки implementation (vulnerable или safe) и result (allowed, denied или not_found).
Показывает результат проверки доступа для каждой реализации

guardlab_auth_login_attempts_total - метка result: success или failure. Считает успешные и неуспешные попытки входа администратора.

guardlab_lab_lifecycle_actions_total - метка action: created, updated, archived или restored. 
Считает успешно выполненные действия администратора над лабораториями.

Метрики сделаны счётчиками

## Метрики PostgreSQL

Для PostgreSQL используется postgres-exporter
Для экспортёра создан отдельный пользователь postgres_exporter. 
Ему выданы роль pg_monitor для чтения статистики PostgreSQL и право подключаться к базе guardlab.
Экспортёр отдаёт метрики на /metrics порта 9187

## Проверка

Для просмотра метрик VMSingle

```
kubectl port-forward -n monitoring svc/vmsingle-vm-single-victoria-metrics-k8s-stack 8428:8428
http://localhost:8428/api/v1/label/__name__/values
```


Статус сбора vmagent доступен на его странице targets. Для этого нужно пробросить порт 8429 его Service и открыть http://localhost:8429/targets
